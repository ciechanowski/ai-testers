# S02L04: prompty AI

## AI Prompty

Trzy prompty z zadania. Wykonujesz co najmniej jeden na własnym materiale i wklejasz wynik
do `solution-<imie>.md`. Treść promptów jest po angielsku, tak wyglądają w repo; polski
zostaje w omówieniu.

### 1. MCP: szkielet specu

Playwright MCP czyta żywe drzewo dostępności, więc lokatory pochodzą z prawdziwej strony,
a nie z pamięci modelu.

```
Using Playwright MCP: navigate to http://localhost:5173/payouts, take a
browser_snapshot of the region with data-testid "payouts-panel", and use
browser_generate_locator for the tab navigation and for the two action controls
at the bottom of the recipient card.

Then write a Playwright VRT spec skeleton that screenshots
getByTestId('payouts-panel') and adds toMatchAriaSnapshot() for the tab
navigation. Use role-based locators from the snapshot, not CSS.

Do NOT add masking, clock stabilization or thresholds - I will review the page
myself and add them. Tell me instead which elements you suspect are
non-deterministic, and why.

One more thing: compare the two action controls at the bottom. Report what role
each one exposes in the snapshot, and whether that matches how it looks.
```

### 2. Audyt layoutu i18n

Jedyny mechanizm, który wykrywa błąd DE, pixel diff go nie pokaże, bo błąd siedzi już
w baselinie. Załączasz trzy zrzuty tej samej strony w tym samym viewporcie.

```
I'm attaching screenshots of the same page (/payouts) at the same viewport in
three languages: English [image 1], Polish [image 2], German [image 3].

Context: the UI strings come from i18next resource files. German compound nouns
are typically 30-40% longer than their English equivalents. The layout is
Tailwind CSS.

Task:
1. For each language, list every element whose text overflows, is clipped, is
   truncated with an ellipsis, or overlaps a neighbour.
2. Classify each observation:
   - "bug" - content is unreachable or unreadable (a clipped button label, text
     escaping its container)
   - "intended" - the layout reflows or wraps and stays readable
   - "i18n-expected" - the value legitimately differs per locale (currency
     symbol, number or date format)
3. For each "bug", name the likely Tailwind cause (a fixed width, a missing
   min-w-0 on a flex child, whitespace-nowrap with overflow-hidden, absent
   break-words) and the fix.
4. Which of these would a pixel diff against an existing baseline catch, and
   which would it miss because the baseline already contains the bug?

Format: a markdown table with columns: element, language, observation,
classification, tailwind cause, fix. Then a short verdict paragraph answering
question 4.
```

### 3. Review baseline'u ARIA

`.aria.yml` jest czytelny dla człowieka, w przeciwieństwie do PNG, to jedyny baseline, który
da się przeczytać w review pull requesta.

```
Below are two ARIA snapshots generated by Playwright for the same component in
two locales.

[paste tests/__screenshots__/desktop-light/.../payouts-tabs-en.aria.yml]
[paste tests/__screenshots__/desktop-light/.../payouts-tabs-de.aria.yml]

Task:
1. Ignoring the translated accessible names, is the STRUCTURE identical (same
   roles, same nesting, same node count)? List any structural difference.
2. Here is the ARIA snapshot of the two action controls on the same page:

   [paste the aria snapshot of payouts-submit and payouts-export]

   Do any nodes appear as plain "text" where an interactive role (button, link)
   would be expected? For each, explain what a keyboard or screen-reader user
   loses.
3. Rewrite the offending markup using native HTML elements, and give the
   corrected .aria.yml I should expect after the fix.
4. State explicitly which of these problems a pixel screenshot could never
   detect, and why.

Be concrete: quote the exact YAML lines you refer to.
```

### Zasada kontekstu

Modelowi podajesz **fakt o stronie**, nie gotowy wniosek. Piszesz „stringi pochodzą z i18next,
niemieckie złożenia bywają dłuższe”, a nie „przycisk jest zepsuty”. Model ma sam zobaczyć,
co widzi, inaczej tylko potwierdzi twoją tezę.

### Granica

Długość tekstu to **pre-check**, nie dowód. Werdykt „to bug, a to świadomy kompromis”
podejmujesz ty, patrząc na raport. Pełny audyt dostępności (`@axe-core/playwright`,
Lighthouse) czeka na S04/S05, tutaj go nie ruszamy.
